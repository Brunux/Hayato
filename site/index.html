Real Debian arm64 for Chromebooks & ARM64 boards.
Keyboard first. Light. Fast. Fun.

Built to turn 4 GB ARM Chromebooks, SBCs, and VMs into snappy daily drivers. Plain Debian forky underneath, a swayfx desktop on top, and one Rust binary (hayato) that handles the menus, login screen, 16 themes, Golden Eagle screensavers, games, AI tools, and disk installer.

01 · Boot, Kernel & Hardware
devices/ · core/

          
    
            
  • 4 ready-to-flash ARM64 targets: google-asurada (Hayato MT8192), google-kukui (Kukui / Lenovo Duet MT8183), arm64-uefi (UEFI laptops, QEMU/UTM/Parallels VMs, RPi 4/5 with EDK2), and arm64-extlinux (U-Boot SBCs).
    • 
            
  • 3 bootloaders, one codebase: ChromeOS depthcharge (lz4 signed FIT), standard uefi (systemd-boot), and U-Boot extlinux — all handled cleanly through the same boot backend.
    • 
            
  • Tuned kernels + broad firmware: custom 7.2.7-mt81 kernel for MediaTek Chromebooks, plus Debian linux-image-arm64 with Wi-Fi/SoC firmware (brcm80211, qcom-soc, atheros, iwlwifi, realtek, mediatek) baked in.
    • 
            
  • Tuned for 4 GB RAM: MGLRU, zram (lz4) swap, kyber I/O scheduler, MMC IRQ balancing, and an easy tool to turn a spare SD card into extra swap (hayato menu swap).
    • 
            
  • Chromebook stuff that just works: USB-C DisplayPort out, tablet-mode auto-rotation + wvkbd on-screen keyboard, keyd Search-key & top-row mapping, backlight, audio, and webcam.
    • 
            
  • Never touches stock firmware: your device's bootloader stays untouched, so you can always go back.
    • 
          

        


        
        

          
02 · Boot Splash, Login & Screensavers
plymouth · greetd · tte

          
    
            
  • Pixel-hacker Plymouth boot splash: custom 5×8 pixel Hayato_ with cyan decode glyphs (0 1 # / = +), blinking orange underscore, and plymouth.ignore-serial-consoles so it actually shows up on ARM64 boards.
    • 
            
  • Minimalist hayato-greeter (greetd): pure-Rust login screen with the half-block Hayato_ hero, subtle glitch pulse, user pills, blinking cursor, clean icon-only ^T ^Z ^R ^P buttons, and an optional bottom-right clock.
    • 
            
  • Live login themes & settings: tap F4 / ^T to flip through all 16 themes right on the login screen, or tweak defaults anytime in hayato menu greeter.
    • 
            
  • 3 Golden Eagle screensavers: three 2×2 pixel-block Golden Eagles (Crest, Dive, Head) cycling tte effects (decrypt, beams, binarypath, rain, sweep, wipe) in gold → amber → cyber-cyan.
    • 
            
  • Clean idle chain: swayidle kicks in the Golden Eagle screensaver at 150s, locks with themed swaylock at 300s, turns off the display at 360s, then suspends.
    •

swayfx · waybar · hayato-theme

05 · Retro & Web Games, Notes & Media
hayato-games · editxr · xournalpp

06 · AI Agents, MCP & Dev Tools
hayato-mcp · whisper · apt

          
    
            
  • Safe desktop MCP server (hayato mcp): 18 stdio tools split into read (status, screenshot, windows, theme, packages, clipboard), act (open menus, switch themes, notify), and propose (install, format, swap, power — only opens a confirmation screen for you, never runs destructive stuff on its own).
    • 
            
  • AI agents launcher: menu agents (Alt+Ctrl+Shift+A) manages Claude Code, Codex, OpenCode (already wired to hayato-mcp), Gemini CLI, and GitHub Copilot with isolated accounts.
    • 
            
  • Drop-down Quake console & Ask: hit Alt+` to slide down a 60% scratchpad terminal anytime, or run hayato ask for a quick answer in-window.
    • 
            
  • Offline voice dictation (Alt+Ctrl+X): parecord → whisper-cli → wtype. Hold for push-to-talk or tap for hands-free — types straight into whatever window you're in, 100% offline.
    • 
            
  • Encrypted dev profile backup (menu dev): pack up your dotfiles, SSH/agent configs, and state into a GPG AES-256 archive and restore it on another machine in seconds.
    • 
            
  • Cloudsmith APT repo: run hayato-apt enable once and normal apt upgrade keeps hayato, hayato-core, and board packages current.
    • 
          

        


        
        

          
07 · Disk Installer, Backups & Security
installer · audited v0.6.1

          
    
            
  • 6-step Rust disk installer: hayato installer (or headless --clone) checks your hardware, power, and disks before cloning the live OS onto internal storage — defaults to Cancel, double-confirms, and blocks you from wiping the drive you booted from.
    • 
            
  • Full system snapshots: backup-system.sh and restore-system.sh let you back up and restore a whole install without guesswork.
    • 
            
  • 535+ live health checks: check-core.sh, check-device.sh, check-desktop.sh, and check-system.sh sanity-check the kernel, hardware, fonts, and desktop config.
    • 
            
  • Locked-down defaults (audited in v0.6.1): SSH off by default on fresh images, 0700 home directories, loopback-only VNC, SHA256-pinned binaries, plugdev-only automount, bounded notify sockets, and no raw sh -c shell injection paths in the Rust suite.

        RELEASE v0.6.1 · FLASH & GO
        
Try it on USB/SD, then install to disk

        
Grab the image for your board from v0.6.1 Releases, verify it with SHA256SUMS, flash it to a card or USB stick, and boot. When you're ready to keep it, hayato installer clones the running system straight onto internal storage.

01.Verify & flash external media

          
Download SHA256SUMS alongside your image and write it to microSD or USB (replace <target> and /dev/sdX):

          

            

$ sha256sum -c --ignore-missing SHA256SUMS
$ xz -dc <target>.img.xz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync

          

        


        

          
02.Boot & log in

          
On UEFI/VMs/U-Boot boards, pick the flashed drive in your boot menu. On Chromebooks (google-asurada / google-kukui), enable external boot in Developer Mode and press Ctrl+U:

          

            

$ crossystem dev_boot_usb=1 dev_boot_signed_only=0

          

          
hayato-greeter starts automatically. Live user: brunux · password: debian. Run passwd before daily use.

        


        

          
03.Install to internal disk & enable APT upgrades

          
Press Alt+Space → Install Hayato (or run hayato installer) to clone onto internal storage, and enable the signed Cloudsmith APT repo for rolling hayato updates:

          

            

$ hayato installer          # 6-step guided TUI (or: sudo hayato installer apply --clone --confirm)
$ sudo hayato-apt enable && sudo apt update && sudo apt upgrade

          

        

      


      

        Read before flashing: Stock firmware is never touched. Enabling ChromeOS Developer Mode wipes ChromeOS, and hayato installer erases the chosen internal disk (the running boot media is locked out). Keep recovery media handy.
      

    

  


  
  

    

      

        HOW IT'S BUILT
        
Three small repos, one clean umbrella.

        
Instead of one giant messy repo, Hayato is split into three focused submodules so board quirks never leak into the desktop and bootloaders stay separate from the UI:

        
core/ builds the Debian forky rootfs, handles the three boot backends (depthcharge, uefi, extlinux), backup/restore, and release imaging.

        
desktop/ holds the swayfx config, 16-theme engine, Plymouth splash, Golden Eagle screensavers, manual, and the Rust hayato codebase.

        
devices/ keeps kernels (7.2.7-mt81 and mainline fragments), udev/keyd/IRQ tweaks, and per-board overlays neatly isolated.
