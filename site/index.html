FROM EXTERNAL MEDIA TO DISK

Flash an image, install to internal storage

Boot the live image from microSD or USB, then clone the running system onto internal storage with our pure-Rust installer.

Download a release image

Get google-asurada.img.xz (Hayato MT8192), google-kukui.img.xz (Kukui / Lenovo Duet MT8183), arm64-uefi.img.xz (ARM64 UEFI laptops/servers, QEMU/UTM/Parallels VMs, and Raspberry Pi 4/5 with EDK2 UEFI), or arm64-extlinux.img.xz (U-Boot SBCs such as Rockchip/Allwinner/Amlogic/Pi U-Boot with SPI or SPL boot) plus SHA256SUMS from v0.5.1 Releases.

Verify and write the drive

$ sha256sum -c --ignore-missing SHA256SUMS
$ xz -dc <target>.img.xz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync

Replace <target>.img.xz and /dev/sdX (or /dev/mmcblk1) with your image and card/USB device. dd overwrites the entire drive. On arm64-extlinux SBCs without SPI/eMMC U-Boot, flash your board's U-Boot SPL into the reserved 1–16 MiB pre-partition gap after dd.

Boot the external drive

On UEFI laptops/VMs (QEMU/UTM/Parallels) or SBCs with U-Boot in SPI/eMMC, choose the flashed drive in your firmware boot menu (for Raspberry Pi 4/5 on arm64-uefi, use RPi4/RPi5 EDK2 UEFI firmware on SPI/SD ESP; on arm64-extlinux boards without SPI U-Boot, write your board's U-Boot SPL into the 1–16 MiB gap). On Chromebooks (google-asurada or google-kukui), enter developer mode and allow external boot:

$ crossystem dev_boot_usb=1 dev_boot_signed_only=0

Insert the card and press Ctrl+U / pick external disk in the firmware menu.

Log in, then change the password

hayato-greeter starts automatically: live user brunux, password debian, passwordless sudo. Run passwd before using it daily.

Install to the internal disk

Alt Space opens the root menu: pick Install Hayato (or run hayato installer in a terminal; headless: sudo hayato installer apply --clone --confirm). It checks power and free disks, writes the target's boot layout (depthcharge, uefi, or extlinux), and defaults safely to Cancel until confirmed.

On Depthcharge Chromebooks (google-asurada & google-kukui), CONFIRM=yes sudo /usr/libexec/hayato/install-emmc.sh remains available as a manual/debug fallback.

Let it finish, then reboot

The live clone copies the running system, updates boot metadata, and writes /etc/hayato/installation last. Remove the external drive and reboot to the internal disk.

Read before you flash. Stock system firmware is never overwritten. Developer mode wipes ChromeOS on Chromebooks, and the installer erases the selected internal disk. Keep a second computer and recovery media at hand; the running boot drive cannot be picked as the target.

UNDER THE HOOD

Modular by design.

Hayato pairs Debian forky userland with a clean three-submodule architecture: hayato-core handles Debian assembly and pluggable boot backends, hayato-desktop owns the swayfx session and Rust hayato workspace, and hayato-devices isolates kernel recipes and board quirks.

google-asurada and google-kukui share our tuned 7.2.7-mt81 kernel (started from postmarketOS/Nura), while arm64-uefi and arm64-extlinux pair Debian's mainline linux-image-arm64 and Devicetree bundle with broad multi-vendor firmware (brcm80211, qcom-soc, atheros, iwlwifi, realtek, mediatek) to give Raspberry Pi 4/5 (via EDK2 UEFI or U-Boot), Rockchip/SBCs, ARM64 UEFI laptops, and QEMU/UTM VMs a ready-to-boot Debian arm64 image with automatic apt upgrade kernel sync.
