# v0.5.0 — frictionless in-window UX and native `lazyos-greeter`

Everything interactive stays inside its window, anticipates what you opened it
for, and keeps tool actions separate from domain results. At boot, `tuigreet`
is retired: `greetd` now launches **`lazyos-greeter`**, a native Ratatui login
surface themed from the same palette engine as the desktop session, with its
own defaults editor.

## What changed since v0.4.3

### Frictionless in-window UX (spec 020)

- **Anticipate primary intent on open**:
  - `lazyos menu net` renders cached Wi-Fi networks immediately while triggering a
    background rescan in-place.
  - `lazyos menu bluetooth` scans automatically on open and right after power-on.
  - `lazyos menu clean` computes reclaimable cache space asynchronously before
    confirmation.
  - `lazyos menu calc` evaluates expressions live as you type with a movable
    cursor and Python-style operators.
- **In-window tool lifecycle and transient/persistent notices (`ActionNotice`)**:
  - Short actions show an in-window braille spinner and status banner instead of
    closing the menu and emitting external `notify-send` toasts.
  - Heavy multi-step or streaming tasks run inside `TaskView` with step checklists,
    progress bars, and persistent completion cards.
  - Routine discovery clears its status on completion, positive transitions
    auto-clear after 3 seconds, and actionable errors or space-freed summaries
    persist until dismissed.
- **Separate actions from domain results (`ActionStrip`)**:
  - Tool-level actions (`Rescan`, `Share QR`, `Clean all safe`, `Mute`, `Mixer`,
    `Refresh`, `Save PNG`, `Settings`, …) live in a dedicated horizontal
    `ActionStrip` (`Tab` / `Ctrl+<Key>` / mouse click), leaving `ListState` strictly
    for domain rows.
  - Generated QR codes (`menu qr` and `menu net` Share QR) save high-resolution
    PNGs (`s` / `Ctrl+S`) under `~/Pictures/Screenshots/<YYYY-MM-DD>/`.
- **Headless voice-to-text dictation (`dictate`, `Alt+Ctrl+X`)**:
  - Holding `Alt+Ctrl+X` records push-to-talk and transcribes on release via
    `taskset -c 4-7 whisper-cli -t 4` without stealing Wayland keyboard focus
    from `wtype`.
  - A quick tap or Root Menu launch starts hands-free recording with synchronized
    stop/cancel controls across `lazyos-notify` action buttons, Waybar's
    `custom/busy` spinner (`bar-busy`), and the Root Menu's dynamic
    `Stop dictation` row.
- **UI & build fixes**: adopted `foot` auto-copy defaults, isolated the private
  D-Bus test bus in `tests/notify.rs` over abstract `/tmp/dbus-*` sockets for CI
  runners, and polished density-aware card geometry, live window resizing, and
  inline previews.

### Native `lazyos-greeter` & Greeter Settings (spec 021)

- **`lazyos-greeter` replaces `tuigreet` 0.9.1**:
  - Implemented as the `greeter` command inside `lazyos` (`/usr/bin/lazyos-greeter
    -> /usr/bin/lazyos`, `Shape::Full`) over a pure-Rust `UnixStream` JSON `greetd`
    IPC client (`src/greeter/ipc.rs`).
  - `/usr/bin/lazyos-greeter --session` generates theme-matched `foot.ini`,
    `sway.conf`, and wallpaper PNG assets, then launches minimal `sway` +
    fullscreen `foot` on VT7—automatically falling back to inline Ratatui TUI on
    the raw console if `sway` or `foot` cannot start (`--tty` forces the TTY
    path).
  - Supports clickable user pills + `[+ Other]` manual login, masked PAM
    secrets and multi-step challenges, Wayland/X11 `.desktop` session discovery
    (`DesktopNames` exported as `XDG_CURRENT_DESKTOP`), live theme cycling across
    all 16 palettes (`F4` / `Ctrl+T`), session switching (`F2` / `Ctrl+S`),
    Cancel-first confirmations for Sleep / Reboot / Shut down, and safe
    in-session testing via `lazyos greeter --preview`.
- **Interactive Greeter Settings (`lazyos menu greeter` / `lazyos greeter settings`)**:
  - Accessible from **Settings → Login screen (Greeter)**, the Command Palette
    (**Greeter settings**), or **`Ctrl+G`** / **`F9`** / **Settings** inside
    `lazyos greeter --preview`.
  - Configures `/etc/lazyos/greeter.toml` (`follow_user_theme`, fixed/default
    `theme`, `show_user_pills`, `remember_user`, `default_session`,
    `remember_session`, `clock_24h` 24h/12h toggle, `show_power_actions`, and
    custom `greeting` text) with inline searchable pickers and Cancel-first reset
    to defaults.

## Validation

The rootfs and distributable image are built on the Chromebook from this
repository (`scripts/build-rootfs.sh`, `install-kernel.sh`,
`install-swayfx.sh`, `install-workstyle.sh`, `install-lazyos.sh`, and
`scripts/make-release.sh`): mainline Linux 7.2.7 (`7.2.7-mt81`), `swayfx` 0.6
on `scenefx` 0.5, `workstyle` 0.8.2, `debootstrap` for Debian `forky/arm64`,
and a signed depthcharge FIT kpart (`futility: dev-signed FIT, preamble 2.2,
body verification succeeded`). The image, its `.img.xz`, the root filesystem
tarball, and the standalone `.kpart` are sanitized and asserted clean by
[`scripts/lib-dist.sh`](../../scripts/lib-dist.sh), and `SHA256SUMS` covers
the four disk artifacts.

`VERSION` is `0.5.0`, matching `lazyos --version`. All **530** workspace tests
pass (`cargo test --workspace --all-targets`, with 1 pre-existing ignored test
in `tests/files.rs`), and `cargo fmt --all --check` and
`cargo clippy --workspace --all-targets -- -D warnings` are clean.

## Assets

| asset | what it is |
|---|---|
| `google-asurada.img.xz` | 6 GiB disk image (`3.3G` data): the three ChromeOS GPT partitions (kernel, `/boot`, root), ready for `dd` |
| `google-asurada-rootfs.tar.zst` | the same root filesystem as a tarball (with `/boot` inside), for writing your own card with `scripts/write-sd.sh` |
| `google-asurada.vmlinuz.kpart` | the signed FIT kernel partition of that image; it embeds the image's `root=UUID`, so it belongs to this image and no other |
| `lazyos`, `lazyos-notify`, `spike-sixel` | `aarch64` framework binaries built from this tag by `.github/workflows/release.yml` |
| `SHA256SUMS` | SHA-256 checksums (`make-release.sh` covers the disk/tarball/kpart assets; CI covers the framework binaries) |

```sh
sha256sum -c SHA256SUMS
xz -dc google-asurada.img.xz | sudo dd of=/dev/mmcblk1 bs=4M conv=fsync
```

On the Chromebook: developer mode, `crossystem dev_boot_usb=1 dev_boot_signed_only=0`,
insert the card, and pick **external disk** in the firmware menu. It boots
into **`lazyos-greeter`** on VT7 — user `brunux`, password `debian`, passwordless
sudo. **Change the password before using it for anything real.**
`scripts/install-emmc.sh` installs it to internal storage, and on the card
`Alt+Space → Install LazyOS` (or `lazyos installer`) is the same call with
interactive pre-flight and confirmation gates.

## What it does not carry

The artifact is sanitized and asserted clean by
[`scripts/lib-dist.sh`](../../scripts/lib-dist.sh): no Wi-Fi profiles (a released
image knows no network and asks for one), no SSH host keys and no `machine-id`
(both generated on first boot, so every installation has its own identity), no
OpenCode sign-in, and no personal files beyond the session configuration this
repository ships.

## Known limitations

- **`lazyos-notify` is resident** for the session, because a notification
  daemon is what owns the bus name; it is an agreed exception next to
  `cliphist`'s watcher and `workstyle`, and idles without redrawing when no
  card is up.
- **The night light cannot reach the external monitor.** MT8192's second display
  path (OVL1→RDMA1→DPI) has no gamma block bound, so `wlsunset` cannot set
  gamma on an external 1080p monitor.
- **The camera portal is not implemented**, so Flatpak apps do not see a
  camera while Firefox and native apps work.
- **The three-finger tab swipes do nothing when Firefox runs on Xwayland**
  (`MOZ_ENABLE_WAYLAND=0`): the criteria need an `app_id`, and an X11 window has
  none.
- **The profile archive does not carry OpenCode's sign-in** (it lives in
  `~/.local/share/opencode/opencode.db`), and a Firefox profile copied while
  running is each database at its last checkpoint.
- **Wayvnc is loopback-only and read-only** (`lazyos menu vnc` shows the SSH
  tunnel command).
- **The installer refuses to run from the disk it would overwrite**: install to
  eMMC from a booted microSD card.
- The image is 6 GiB (`IMAGE_SIZE_MIB=6144`), leaving unused space on larger
  cards unless written via `scripts/write-sd.sh`. The tarball's `/etc/fstab` is
  the unconfigured one left by the build.
- Artifacts are not byte-reproducible yet (FIT timestamp, filesystem UUIDs).
- There is no hardware video decoder, and Vulkan is not usable (PanVK answers
  *Mali-G57 not supported*); rendering uses EGL and Panfrost.
