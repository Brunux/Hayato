# v0.6.0 — Hayato: the golden eagle, Tokyo Night, and one name everywhere

The release where the distribution changes its name. **Hayato** is an old
Japanese word for a falconer — the person whose bird comes back to the hand —
and the session now looks like the word: a golden eagle on a pixel grid, Tokyo
Night by default, and the promise **light. fast. fun.**

It is one rename in one release rather than two: the binary, the crates, the
directories, the units, the launcher IDs, the icon theme and the MCP server all
say `hayato` in 0.6.0, so nothing has to be translated for the rest of the 0.6
line. The old name survives only in history — `reports/`, the release notes
before this one, specs 001–025 and the design notes — where it is a record of
what happened rather than a claim about today.

## What changed since v0.5.1

### The name

- **One pass, one allowlist.** `LazyOS` → `Hayato` in prose, `lazyos` →
  `hayato` in identifiers, `LAZYOS_*` → `HAYATO_*` in the environment. The
  multicall binary and its `argv[0]` links (`hayato-menu`, `hayato-greeter`,
  `hayato-notify-history`, `hayato-games`), the eight crates, `/etc/hayato`,
  `~/.config/hayato`, `/usr/share/hayato`, `/usr/libexec/hayato`,
  `/usr/share/doc/hayato`, the `org.hayato.*` entries, the `Hayato` icon theme,
  `ID=hayato`, `PRETTY_NAME="Hayato 0.6.0"` and the default hostname.
- **The MCP server is `hayato`**, and its manual resources moved from
  `lazyos://manual/*.md` to `hayato://manual/*.md`; the shipped
  `~/.config/opencode/AGENTS.md` pins the new manifest.
- **Device codenames are untouched.** `google-asurada` is still the Hayato
  Chromebook — that is Google's name for the hardware — and the brand never
  names a device, a kernel family or a board.

### The brand

- **The mark is a grid, not a vector.** `brand/mark-48.txt` is a 48×48
  character grid and the only source: `scripts/make-brand.py` samples it 1×1,
  2×2 and 3×3 into the 48, 24 and 16 px icons, and draws the wallpaper, the
  social card, the fastfetch wordmark and the idle art from the same cells, so
  no surface is a resample of another and the screensaver cannot drift from the
  launcher.
- **The wordmark is `Hayato_`** with the trailing underscore in the accent, and
  the tagline is **light. fast. fun.** The bar carries `H_`, the wordmark's
  letter and its cursor.
- **No Japanese visual identity.** No kanji or kana appear in the mark, the
  wordmark, the wallpaper, the installer or the interface. The word carries the
  philosophy and the philosophy is written in prose, in `brand/README.md` and
  `01-welcome.md`.
- **The serpent belongs to the idle screen** and nowhere else: a coiled block
  snake under the wordmark, never a logo and never a wallpaper.

### Tokyo Night is the default theme

- First in the `Alt+Shift+T` cycle, and the answer everywhere a theme was still
  assumed: the greeter's config template and fallback, `theme preview`,
  `theme next`, `theme render`, the MCP resource, the appearance picker, the
  notes editor's theme sync and the greeter's settings rows. A fresh image no
  longer boots a Solarized greeter into a Tokyo Night session.
- All fourteen committed surfaces are rendered from it (foot, waybar, mako,
  GTK 3/4, btop, nvim, starship, swaylock, greeter, games, fzf, lazygit, sway),
  the glow style is `tokyo-night.json`, and the launcher icons are drawn in the
  palette's cyan `#7dcfff` instead of the brightened Solarized teal.
- Solarized is still one of the sixteen, unchanged.

### Wallpapers: three per theme, reviewed

- Every built-in theme cycles exactly three pictures (48 files). Each one was
  looked at: no wordmark, logo, trademark or third-party character art — the
  Audi Quattro, the LUMON card, the OMARCHY poster and the omarchy-branded
  files are recorded as rejected with their reason in `brand/wallpapers.md`.
- `scripts/fetch-wallpapers.py` is the manifest and installs into both the tree
  and `~/Pictures/Wallpapers`, which is the path the sway drop-in names.
- **A missing wallpaper no longer takes the session down.** The renderer walks
  the theme's three, then the brand wallpaper, and if none is installed it
  comments the line out; sway used to refuse the whole config on a missing
  `output * bg` file, which is how a dev machine lost its session.

### A faster profile export

- `hayato-profile export` no longer compresses twice: `gpg` was running its own
  zlib pass over a stream `zstd` had already compressed. Measured on 518 MB of
  home data, that pass cost 23 s and saved 0.04 %; with `--compress-algo none`
  and `zstd -1` the export went from **26 s to 2.7 s** with the same file size.
- The free-space check now reserves the uncompressed size, because a profile is
  mostly pictures, models and wine prefixes, where the archive is as large as
  the input.

### Small things

- The glyph table is regenerated against the current `fonts-nerd-symbols`, so
  the font pin matches the package the image installs.
- The icon theme's `index.theme` lists the 16 and 24 px directories the mark
  ships in; a directory the index omits is one GTK never looks in.
- The console banner, the test checklist and the manual all say what the session
  now shows.

## Validation

- `cargo test --workspace --all-targets`, `cargo clippy -D warnings` and
  `cargo fmt --check` in `desktop/`.
- `./build.sh validate`: devices, core and umbrella checks, plus the guard that
  fails when the old brand name appears in the product tree.
- `scripts/fetch-wallpapers.py --check`: every theme declares exactly three
  pictures and every file is present.
- `scripts/make-brand.sh` regenerates every brand file from the grid; the
  outputs are idempotent.
- `sway --validate` on a session whose theme drop-in names a picture that is not
  installed: the config loads instead of failing.
- The four changes merged through pull requests: hayato-core#4,
  hayato-devices#2, hayato-desktop#39, Hayato#55.

## Assets

`google-asurada` is built and attached first; the release pipeline adds the other
three targets to this same release.

- `google-asurada.img.xz` (`6144 MiB`) — Google Hayato Chromebook (MT8192,
  `mediatek-mt81` kernel, `depthcharge`)
- `google-kukui.img.xz` (`6144 MiB`) — Kukui/Duet family (MT8183)
- `arm64-uefi.img.xz` (`8192 MiB`) — generic ARM64 UEFI, VMs, RPi 4/5 via EDK2
- `arm64-extlinux.img.xz` (`8192 MiB`) — U-Boot SBCs

`SHA256SUMS` travels beside them; verify with `sha256sum -c --ignore-missing SHA256SUMS`.

## What it does not carry

- No history rewrite: the old name stays in the reports, the previous release
  notes and specs 001–025.
- No device rename: `google-asurada` and `google-kukui` keep their codenames.
- No change to the image layout, the boot backends or the installer's data
  model.

## Known limitations

- **`hayato-notify` is resident** for the session next to `cliphist` and
  `workstyle` to own `org.freedesktop.Notifications`; it idles without redrawing.
- **MT8192 external display gamma**: OVL1→RDMA1→DPI has no gamma block bound, so
  `wlsunset` applies night light on the built-in panel only.
- **Wayvnc is loopback-only and read-only** (`hayato menu vnc` prints the SSH
  tunnel command).
- **Camera portal & Xwayland gestures**: the Flatpak camera portal is absent
  (native browsers work), and three-finger Firefox tab swipes require native
  Wayland.
- **Fixed image sizes**: `google-asurada` / `google-kukui` (`6144 MiB`) and
  mainline ARM64 images (`8192 MiB`) leave extra card space unallocated unless
  written via `scripts/write-sd.sh`.
- **Generic ARM64 board firmware/SPL**: `arm64-extlinux.img.xz` leaves the
  `1–16 MiB` pre-partition gap empty, and Raspberry Pi 4/5 needs RPi EDK2 UEFI
  (`arm64-uefi`) or U-Boot (`arm64-extlinux`).
- **MT81 GPU codecs**: no hardware video decoder; Panfrost GL/EGL handles
  compositing (PanVK does not support Mali-G57/G72).
- **Repository names**: the four GitHub repositories are renamed to `Hayato`
  and `hayato-*` alongside this tag; until that lands, links in the README and
  the site point at the new names.
