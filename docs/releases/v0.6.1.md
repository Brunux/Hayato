# v0.6.1 — In-place `.deb` upgrades, Cloudsmith APT, and hardware polish

The release where Hayato moves from full-image reinstalls to in-place Debian
package upgrades. Every component of the distribution — the `hayato` desktop
framework, `hayato-core` runtime and boot hooks, `hayato-device-<board>`
overlays, `linux-image-hayato-<flavor>` custom kernels, `swayfx`, `workstyle`,
`retroarch`, and the libretro cores — now ships as a `.deb` package published to
the Hayato Cloudsmith APT repository (`debian/forky`) and archived with signed
APT metadata on GitHub Releases.

## What changed since v0.6.0

### In-place `.deb` distribution & Cloudsmith APT

- **Full `.deb` coverage across all three submodules**:
  - `hayato_<ver>-1hayato1_arm64.deb` (`desktop/scripts/build-hayato.sh`)
    packages `/usr/bin/{hayato,hayato-notify,hayato-games}`, all
    `hayato --symlinks`, `/usr/share/hayato/games/`,
    `/usr/libexec/hayato/check/30-desktop.sh`, the Sway system overlay, and the
    user skeleton (`/usr/share/hayato/skel/`). Its `postinst` preserves symlinks
    and executable helpers in `~/.config/bin/`, updates
    `~/.config/opencode/{opencode.json,AGENTS.md}` without touching personal
    credentials (`cli.json`, `service.json`), refreshes fontconfig and icon
    caches, and re-renders the active theme headlessly.
  - `hayato-core_<ver>-1hayato1_arm64.deb` (`core/scripts/build-core-deb.sh`)
    packages `/usr/libexec/hayato/`, system tuning drop-ins, unified kernel and
    initramfs boot hooks, `/usr/share/keyrings/hayato-archive-keyring.gpg`, and
    `/etc/apt/sources.list.d/hayato.sources`.
  - `hayato-device-<board>_<ver>-1hayato1_arm64.deb`
    (`devices/scripts/build-device-deb.sh`) packages `/etc/hayato/*`,
    `20-device.sh`, `modules-initfs`, and board overlays (`udev`, `keyd`, ALSA
    UCM2, IRQ tuning).
  - `linux-image-hayato-<flavor>_<kver>+hayato<ver>-1hayato1_arm64.deb`
    (`devices/scripts/build-kernel.sh` with `BUILD_DEB=yes` by default) packages
    the kernel image, modules, and device trees in both `/boot/dtbs/` and
    `/usr/lib/linux-image-<release>/`.
  - Monotonic libretro core package versions (`1:<ver>+git.<shortrev>+hayato1`)
    in `build-fbneo.sh` and `build-mupen64plus-next.sh` so `dpkg` upgrades stay
    strictly ordered across upstream git pin bumps.
- **`hayato-apt` CLI (`/usr/local/sbin/hayato-apt`)**:
  - `sudo hayato-apt enable` merges the Cloudsmith signing key, enables
    `/etc/apt/sources.list.d/hayato.sources`, and refreshes package lists.
  - `sudo hayato-apt upgrade-from-github` downloads, checksum-verifies, and
    installs the latest release `.deb` packages directly from GitHub Releases
    when offline from Cloudsmith.
  - `hayato-apt build-repo <dir>` generates GPG-signed `Packages`,
    `Packages.gz`, `Release`, `InRelease`, and `Release.gpg` metadata in CI.
- **Automatic `depthcharge` kernel & initramfs partition updates**:
  - `/etc/kernel/postinst.d/zz-hayato-boot` and
    `/etc/initramfs/post-update.d/zz-hayato-boot` now run on `depthcharge`
    Chromebooks (`google-asurada`, `google-kukui`) as well as `uefi` and
    `extlinux`, forwarding `TARGET_KERNEL_RELEASE` to `install-kpart.sh` and
    deduplicating consecutive hook runs via `/run/hayato-boot-synced-<ver>`.

### Desktop & session fixes

- **Green installer progress bar**: `InstallerScreen::draw_progress` uses
  `draw_gauge_with(..., ColorRole::Ok)` so the installation bar stays green all
  the way through 100% instead of turning yellow at 70% and red at 90%.
- **Games library shelf & test discovery**: `checkout_games_data` walks all
  executable ancestor directories (supporting deep Cargo build target layouts in
  CI), and `GamesScreen::draw_shelf` renders `"No games in this view"` with an
  actionable hint on narrow windows when filtered to zero games.
- **Unified default browser helper**: `~/.config/bin/hayato-browser` is now the
  single reader of `xdg-settings get default-web-browser` across
  `Alt+Shift+Return`, `/usr/local/bin/xdg-open`, captive-portal sign-in, and
  Files.
- **Wallpaper cycling**: cycling wallpapers in the theme picker clears any
  custom wallpaper override first.
- **Clipboard watcher**: anchored the `wl-paste` watcher pattern in
  `hayato-clipboard` so its launcher process never matches itself.
- **Profile backup & restore**: pinned `hayato-profile` export and restore to
  the big Cortex-A76 cores (`taskset -c 4-7`) and treated `tar` exit code `1`
  (file changed while reading) as a clean backup.

### Kernel & hardware fixes (`google-asurada` & `google-kukui`)

- **Silent SBS battery polling & responsive charging touchpad**:
  `sbs-battery-eio-is-no-data.patch` maps the MT8192 EC's `EIO` on unimplemented
  optional SBS properties (`time_to_empty_now`) to `-ENODATA`, and
  `sbs-battery-cache-unsupported.patch` caches unsupported properties after the
  first probe — eliminating ~1,300+ journal error lines per boot and stopping EC
  bus contention that caused touchpad lag while charging.
- **USB XHCI IRQ balancing**: `hayato-irq-balance` routes the USB controller
  interrupt off CPU0 alongside MMC storage interrupts so USB drive I/O cannot
  starve EC keyboard/trackpad input on CPU0.
- **Debian `forky` host-tools compatibility**: `build-kernel.sh` passes
  `-include /usr/include/linux/types.h` in `HOSTCFLAGS` when system headers
  reference `__u128`.

## Assets

- `google-asurada.img.xz` (`6144 MiB`) — Google Hayato Chromebook (MT8192,
  `mediatek-mt81` kernel, `depthcharge`)
- `google-kukui.img.xz` (`6144 MiB`) — Kukui/Duet family (MT8183)
- `arm64-uefi.img.xz` (`8192 MiB`) — generic ARM64 UEFI, VMs, RPi 4/5 via EDK2
- `arm64-extlinux.img.xz` (`8192 MiB`) — U-Boot SBCs
- Debian `.deb` packages (`hayato`, `hayato-core`, `hayato-device-*`,
  `linux-image-hayato-mediatek-mt81`, `swayfx`, `libscenefx-*`, `workstyle`,
  `retroarch`, `hayato-libretro-fbneo`, `hayato-libretro-mupen64plus-next`) and
  signed APT repository metadata (`Packages.gz`, `InRelease`, `Release.gpg`,
  `hayato-archive-keyring.gpg`).

`SHA256SUMS` travels beside them; verify with
`sha256sum -c --ignore-missing SHA256SUMS`.
